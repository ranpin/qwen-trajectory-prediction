## 一、项目概述

### 1.1 目标

构建一个完整的行人轨迹预测系统：基于 Qwen3-4B 微调，将轨迹预测建模为文本生成任务，
打通「数据准备 → 微调 → 量化 → NVIDIA Orin 端侧部署 → 交互式 Demo」全链路。

### 1.2 核心价值

- **LLM 驱动**：利用大模型语义理解能力做轨迹预测。
- **可解释**：不仅输出坐标，还用自然语言解释预测理由。
- **端侧部署**：通过 4-bit 量化在 Jetson Orin 上实时推理。
- **完整 Demo**：交互式可视化演示（含基线对比）。

### 1.3 技术栈概览

| 环节 | 选型 | 说明 |
|------|------|------|
| 基座模型 | Qwen3-4B | 参数适中，8GB 显存可微调 |
| 数据 | ETH/UCY + 合成数据 | 体量小，适合有限算力 |
| 微调 | ms-swift QLoRA 4-bit | 单张 RTX 3070 可行 |
| 量化 | GGUF Q4_K_M / AWQ | 精度与速度平衡 |
| 推理 | llama.cpp | Orin 上 CPU+GPU 混合 |
| 部署 | Jetson AGX Orin | 统一内存架构 |
| Demo | Gradio | 浏览器可视化 |

## 二、数据方案

| 数据集 | 角色 | 现状 |
|--------|------|------|
| 合成数据 | 主力训练数据 | 生成器就绪，可按需生成（含归一化选项）|
| ETH/UCY | 真实基准评估 | 5 场景测试集就绪，解析管线打通 |

**为什么以合成数据为主**：pc-3070 训练机无法访问 HuggingFace；合成数据可快速验证全链路；
真实 ETH/UCY 用于诚实评估。数据序列化与合成策略详见技术文档第 2 节。

## 三、评估指标

### 3.1 目标值

| 指标 | 目标 |
|------|------|
| ADE | <0.5m |
| FDE | <1.0m |
| Miss Rate (>2m) | <20% |
| 推理延迟 | <300ms（Orin，长期目标）|

### 3.2 现状小结

单次预测口径下（非 best-of-K）：合成集 ADE 0.82m、真实 ETH/UCY ADE 0.79m，均未达标；
且**真实数据上 CVM 匀速基线反超 LLM**。这是本项目当前最重要的发现，直接驱动「坐标归一化重训」
的验证工作。完整结果与方法学见技术文档第 7 节。

## 五、风险评估

| 风险 | 可能性 | 影响 | 缓解 |
|------|--------|------|------|
| 真实数据精度不及平凡基线 | 已发生 | 高 | 归一化重训；若仍不及则重估方法价值 |
| 3070 显存不足 | 中 | 高 | QLoRA 4-bit，减小 batch |
| 量化精度损失 | 低 | 中 | 对比 AWQ/GGUF 选优 |
| Orin 推理延迟高 | 中 | 高 | 更激进量化或更小模型 |
| 合成数据不够真实 | 高 | 中 | 提升真实数据比例，改进生成器 |

## 六、后续扩展方向

- **短期**：坐标归一化重训验证；多模态预测（输出 K 条 + 概率，对齐 minADE_K）；收紧输出格式降低解析失败。
- **中期**：引入社交/地图信息；迁移到更大数据集（Argoverse 等）；优化延迟至实时。
- **长期**：多传感器融合；闭环仿真验证；车规级方向探索。
