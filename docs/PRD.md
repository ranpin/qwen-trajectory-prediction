## 一、项目概述

### 1.1 目标

构建一个完整的**车辆轨迹预测**系统：基于 Qwen3-4B 微调，将轨迹预测建模为文本生成任务，
打通「数据准备 → 微调 → 量化 → NVIDIA Orin 端侧部署 → 交互式 Demo」全链路。通过
**agent 类型**抽象，同一套流程与模型同时支持车辆（主）与行人。

### 1.2 核心价值

- **车辆为主、多 agent**：车辆/行人统一建模，一个模型按 agent 标签服务两类交通参与者。
- **LLM 驱动 + 可解释**：不仅输出坐标，还用自然语言解释预测理由。
- **端侧部署**：通过 4-bit 量化在 Jetson Orin 上推理。
- **完整 Demo**：交互式可视化演示（含 CVM 基线对比）。

### 1.3 技术栈概览

| 环节 | 选型 | 说明 |
|------|------|------|
| 基座模型 | Qwen3-4B | 参数适中，8GB 显存可微调 |
| 数据 | 合成车辆 + NGSIM（真实车辆）+ ETH/UCY（行人）| 体量小，适合有限算力 |
| 微调 | ms-swift QLoRA 4-bit | 单张 RTX 3070 可行 |
| 量化 | GGUF Q4_K_M / AWQ | 精度与速度平衡 |
| 推理 | llama.cpp | Orin 上 CPU+GPU 混合 |
| 部署 | Jetson AGX Orin | 统一内存架构 |
| Demo | Gradio | 浏览器可视化 |

## 二、数据方案

| 数据集 | 角色 | 现状 |
|--------|------|------|
| 合成车辆 | 主力训练数据 | 自行车模型生成器就绪（巡航/变道/跟车/转弯/环岛，5–40 m/s，含归一化）|
| NGSIM | 真实车辆评估 | 解析管线就绪；数据待手动下载（WAF 对数据中心 IP 返回 403）|
| ETH/UCY | 行人评估 | 5 场景测试集就绪，解析管线打通 |

**为什么以合成数据为主**：pc-3070 训练机无法访问 HuggingFace，真实车辆集获取受限；合成车辆数据
可快速验证全链路与运动学多样性；真实集用于诚实评估。数据序列化、车辆运动学与归一化详见技术文档第 2 节。

## 三、评估指标

### 3.1 目标值

| 指标 | 目标 |
|------|------|
| ADE | <0.5m |
| FDE | <1.0m |
| Miss Rate (>2m) | <20% |
| 推理延迟 | <300ms（Orin，长期目标）|

### 3.2 现状小结

**车辆**（主）：合成车辆 CVM 基线 FDE≈15.3m/MR 66.5%（含转弯变道，非平凡）；车辆 LLM 模型
重训与评估进行中；真实 NGSIM 评估待数据。
**行人**（先行验证的基线结论）：单次预测口径下真实 ETH/UCY ADE 0.79m，**CVM 匀速基线反超 LLM**(0.65)；
**坐标归一化重训未能翻盘**(ADE 0.79→0.81、MR 24%→32%，不升反微降)——说明症结不在坐标框架，而在
「纯文本 LLM 做数值回归、不喂地图」的路线本身。**车辆同理需警惕**（高速近似匀速，
CVM 极强）。完整结果与方法学见技术文档第 7 节。

## 五、风险评估

| 风险 | 可能性 | 影响 | 缓解 |
|------|--------|------|------|
| 真实数据精度不及平凡基线(CVM) | 高（行人已发生）| 高 | 归一化重训；若仍不及则重估「纯文本 LLM 做数值回归」的价值主张 |
| 高速车辆 CVM 极强，LLM 难超越 | 高 | 高 | 引入车道/地图上下文；如实汇报，不粉饰 |
| 真实车辆数据获取受限（NGSIM 403）| 已发生 | 中 | 手动下载 / highD 注册 / rounD；合成先行 |
| 3070 显存/内存不足（8GB VRAM，15GB RAM）| 中 | 高 | QLoRA 4-bit；量化与训练分时执行 |
| 量化精度损失 | 低 | 中 | 对比 AWQ/GGUF 选优 |

## 六、后续扩展方向

- **短期**：坐标归一化重训验证；多模态预测（输出 K 条 + 概率，对齐 minADE_K）；收紧输出格式降低解析失败。
- **中期**：引入社交/地图信息；迁移到更大数据集（Argoverse 等）；优化延迟至实时。
- **长期**：多传感器融合；闭环仿真验证；车规级方向探索。
